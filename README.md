# YMRPC Next

**YMRPC Next** — приложение для Windows, которое показывает музыку из Яндекс Музыки или любого плеера в статусе Discord. Полностью новая реализация на Python + PySide6: собственный Discord IPC-клиент, захват Windows SMTC, синхронизированные тексты, мини-плеер, статистика и оверлей для OBS.

> Версия 0.1.1 — ранняя, но рабочая. Интерфейс и документация на русском, English UI тоже доступен.

**Скачать готовую сборку:** [GitHub Releases](https://github.com/Memovoff/YMRPC-Next/releases/latest) — portable `YMRPC-Next.exe` и ZIP-архив.

---

## Возможности

- **Discord Rich Presence** без bot-токена — через локальный Discord IPC.
- **Два источника музыки с авторежимом:**
  - Windows SMTC — работает с Яндекс Музыкой, Spotify, VLC, AIMP, браузерами и любым плеером, который отдаёт медиасессию.
  - Ynison — состояние Яндекс Музыки с других устройств (телефон, веб), требует входа в аккаунт.
  - Автоматически — локальная музыка в приоритете, трек с телефона подхватывается, когда на компьютере тишина.
- **Правила по приложениям** — игнорировать ненужные источники или поднимать приоритет нужного.
- **Шаблоны статуса** с живым предпросмотром карточки Discord.
- **Синхронизированные тексты** из LRCLIB с запасным вариантом из Яндекс Музыки; отдельное окно караоке и вывод строки в статус.
- **Мини-плеер** поверх всех окон: обложка, управление, перемотка, перетаскивание.
- **Глобальные горячие клавиши** (Ctrl+Alt+…).
- **Оверлей для OBS** и локальный HTTP/SSE API на `127.0.0.1`.
- **Статистика прослушиваний** в SQLite: день/неделя/месяц/всё время, топы, график, экспорт CSV.
- **Автообновление** из GitHub Releases с прогрессом загрузки и проверкой SHA-256.
- **Трей**, автозапуск, тёмная тема, английский язык, single instance.

## Системные требования

- Windows 10 1809+ или Windows 11.
- [Discord](https://discord.com/download) для отображения статуса (не обязателен для остальных функций).
- Для сборки из исходников: Python **3.11–3.13** (проверено на 3.13.2).
- Для OBS-оверлея: OBS Studio с Browser Source.

## Быстрый старт из исходников

```powershell
git clone https://github.com/Memovoff/YMRPC-Next.git
cd ymrpc-next

py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -U pip
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"

.\.venv\Scripts\python.exe run.py
```

Без консольного окна:

```powershell
.\.venv\Scripts\pythonw.exe run.pyw
```

Полезные аргументы:

| Аргумент | Действие |
|---|---|
| `--minimized` | запустить сразу свёрнутым в трей |
| `--version` | показать версию и выйти |

Второй экземпляр приложения не запускается — он просто показывает уже открытое окно.

## Сборка

```powershell
.\build.ps1
```

Скрипт прогоняет `ruff` и `pytest`, собирает portable `.exe` через PyInstaller и кладёт в `dist/`:

- `YMRPC-Next.exe` — один файл, ничего устанавливать не нужно;
- `YMRPC-Next-<версия>-win64.zip` — архив для раздачи;
- `SHA256SUMS.txt` — контрольная сумма.

Варианты:

```powershell
.\build.ps1 -SkipChecks      # без тестов и линтера
.\build.ps1 -NoWebEngine    # компактная сборка без встроенного предпросмотра оверлея
```

Без Qt WebEngine предпросмотр оверлея в приложении показывает заглушку, но сам оверлей и OBS работают как обычно. Сборка не подписана — SmartScreen может предупредить при первом запуске.

## Первый запуск и вход в Яндекс Музыку

1. Запустите приложение и откройте **«Приложение» → «Аккаунт»**.
2. Нажмите **«Войти»** — откроется страница OAuth Яндекса.
3. После входа браузер перенаправит на адрес с `#access_token=...`.
4. Скопируйте **весь адрес** или сам токен и вставьте в поле. Кнопка «Вставить» умеет доставать токен из ссылки.
5. Нажмите **«Войти»**.

Токен нужен для:

- источника **Ynison** (музыка с других устройств);
- обогащения треков: обложки, ссылки, годы, точные названия;
- текстов песен из Яндекс Музыки.

Токен хранится **зашифрованным через Windows DPAPI** в `%LOCALAPPDATA%\YMRPC-Next\token.bin` и привязан к текущему пользователю Windows. В открытом виде он нигде не сохраняется. Если DPAPI недоступен или запись не удалась, приложение не переходит на незашифрованное хранение: вход отменяется с сообщением об ошибке.

Без входа приложение продолжает работать через Windows SMTC, но обложки и ссылки могут быть менее точными.

## Источники музыки

### Автоматически (по умолчанию)

Приложение читает обе подсистемы: Windows SMTC и Ynison. Локальная музыка из Windows всегда в приоритете — если в плеере на компьютере что-то играет, показывается этот трек. Когда на компьютере тишина, подхватывается трек с телефона или веба из аккаунта Яндекс Музыки. Это избавляет от ситуации «включил музыку, а статус пустой».

### Windows SMTC

Приложение читает системные медиасессии (`GlobalSystemMediaTransportControlsSessionManager`) и показывает текущий трек. Поддерживаются Яндекс Музыка, Spotify, VLC, AIMP, foobar2000, MusicBee, браузеры, Telegram и другие плееры.

На странице **«Источники»** можно:

- выбрать конкретную сессию вручную (по умолчанию — автоматически);
- добавить правила `ignore` — приложение не будет учитывать этот источник;
- добавить правила `prefer` с приоритетом — нужный источник выиграет у остальных.

Правила сравниваются с ID и именем приложения без учёта регистра. Например, `chrome` отключит Google Chrome, а `spotify` с приоритетом `50` заставит выбрать Spotify.

### Только Ynison

Режим для тех, кто слушает Яндекс Музыку на телефоне или в вебе и не хочет, чтобы локальные плееры перебивали статус. Приложение подключается к Ynison по WebSocket, используя ваш токен, и показывает трек с другого устройства. Требуется вход в аккаунт. Если на других устройствах ничего не играет, интерфейс останется пустым — это ожидаемое поведение режима.

## Discord

Статус обновляется автоматически при смене трека, паузе и возобновлении. Discord должен быть запущен — приложение само найдёт его IPC-канал и переподключится после перезапуска Discord.

На странице **«Discord»** доступны:

- тип активности **«Слушает»** или **«Играет»**;
- кнопки **«Открыть в браузере»**, **«Открыть в приложении»**, обе или ни одной;
- таймаут паузы и опция «Показывать паузу»;
- вывод текущей строки текста в статус;
- шаблоны `details`, `state` и `large_text`.

### Плейсхолдеры шаблонов

| Плейсхолдер | Значение |
|---|---|
| `{title}`, `{track}` | название трека |
| `{artist}` | исполнитель |
| `{album}` | альбом |
| `{year}` | год |
| `{source}`, `{app}` | имя источника |
| `{device}` | устройство |
| `{progress}` | текущая позиция, `1:12` |
| `{duration}` | длительность, `3:34` |
| `{remaining}` | осталось, `2:22` |
| `{progress_pct}` | процент, `34` |
| `{url}` | ссылка на трек |
| `{lyric}` | текущая строка текста |

Пример: `details = "{title}"`, `state = "{artist} · {album}"`, `large_text = "{progress} / {duration}"`.

Если шаблон пуст или даёт пустую строку, используется название трека или исполнитель. Одиночный символ дополняется невидимым символом, чтобы Discord не отбрасывал поле.

## Мини-плеер и горячие клавиши

Мини-плеер открывается из обзора, трея или по горячей клавише. Он всегда поверх окон, перетаскивается за карточку, запоминает позицию и умеет перематывать трек.

| Комбинация | Действие |
|---|---|
| `Ctrl+Alt+M` | показать/скрыть мини-плеер |
| `Ctrl+Alt+L` | окно текста песни |
| `Ctrl+Alt+P` | пауза/воспроизведение |
| `Ctrl+Alt+→` | следующий трек |
| `Ctrl+Alt+←` | предыдущий трек |
| `Ctrl+Alt+H` | скрыть/показать статус Discord |

Горячие клавиши можно отключить на странице **«Приложение»**. Если комбинация занята другой программой, приложение покажет предупреждение и продолжит работать без неё.

## Оверлей для OBS

Включите оверлей на странице **«Оверлей»**. Сервер слушает только `127.0.0.1` (порт по умолчанию `8765`).

В OBS добавьте **Browser Source** и укажите ссылку:

```text
http://127.0.0.1:8765/?theme=dark&accent=%23ffcc00
```

Рекомендуемый размер — около **520×180**, фон прозрачный. Компактный вид для угла экрана:

```text
http://127.0.0.1:8765/widget?theme=dark&accent=%23ffcc00&compact=1
```

Параметры ссылки:

| Параметр | Значение |
|---|---|
| `theme` | `dark` или `light` |
| `accent` | цвет акцента в URL-кодировке, например `%23ffcc00` |
| `hide` | скрыть блоки: `album,source,progress,time,cover` |
| `compact` | `1` — компактная карточка |
| `idle` | `show` — показывать карточку-заглушку, когда ничего не играет |

Страница оверлея сама формирует готовые ссылки с текущими настройками и умеет копировать их в буфер обмена.

### Локальный API

| Метод | Назначение |
|---|---|
| `GET /` | HTML-оверлей |
| `GET /widget` | компактный HTML-оверлей |
| `GET /api/now-playing` | текущее состояние в JSON |
| `GET /api/stats?period=day\|week\|month\|all` | агрегаты статистики |
| `GET /api/art` | обложка текущего трека |
| `GET /events` | SSE-поток обновлений (раз в секунду) |
| `GET /health` | проверка сервера |

Пример `/api/now-playing`:

```json
{
  "has_track": true,
  "status": "playing",
  "title": "Пыяла",
  "artist": "АИГЕЛ",
  "album": "Пыяла",
  "position": 72.4,
  "duration": 214.0,
  "progress": 0.3383,
  "source": "Яндекс Музыка",
  "art_url": "/api/art?v=1712345678",
  "version": 42,
  "updated_at": 1712345678.12
}
```

API отдаёт `Access-Control-Allow-Origin` только для loopback-origin (например, `http://127.0.0.1:8765`), а запросы с чужим заголовком `Host` отклоняются с кодом `421`. HTML-страницы получают CSP и `X-Content-Type-Options: nosniff`; `/api/art` отдаёт файлы только из каталога кэша обложек, а абсолютный путь к обложке не попадает в JSON. Это защищает локальный API от DNS rebinding и чтения посторонними страницами.

## Статистика

Статистика включается на странице **«Приложение»**. Данные пишутся в SQLite:

- прослушивание засчитывается как трек, если набрано **30 секунд**;
- учитывается фактическое время воспроизведения, паузы не считаются;
- доступны периоды **день / неделя / месяц / всё время**;
- на странице есть график за 14 дней, топ треков и исполнителей, последние прослушивания;
- экспорт в CSV: разделитель `;`, кодировка UTF-8 с BOM — открывается в Excel без настройки.

База: `%LOCALAPPDATA%\YMRPC-Next\stats.db`. При отключении статистики новые записи не создаются.

## Автообновление

Приложение проверяет последний релиз GitHub через API:

```text
https://api.github.com/repos/<owner>/<repo>/releases/latest
```

Репозиторий задаётся на странице **«Приложение»** в поле `owner/repo` (по умолчанию `Memovoff/YMRPC-Next`; если ваши релизы лежат в другом месте, укажите свой репозиторий). Проверка выполняется при запуске (если включено автообновление) и вручную кнопкой.

Запросы к GitHub идут только на `api.github.com`, а файлы — только с хостов GitHub Releases. Редиректы проверяются отдельно, поэтому обновление не может увести загрузку на посторонний или локальный адрес.

Как выбирается файл:

1. `.exe` с `setup`, `install` или `ymrpc` в имени;
2. иначе самый большой `.exe`;
3. если `.exe` нет — `.zip`.

Файл релиза обязан иметь SHA-256 digest (поле `digest` в GitHub API, формат `sha256:<64 hex>`). Ассеты без digest игнорируются: если подходящего файла нет, обновление будет показано, но кнопка установки не появится. После скачивания SHA-256 проверяется ещё раз; при несовпадении файл удаляется и не запускается.

После скачивания:

- **установщик** (`*setup*.exe`, `*install*.exe`) запускается, приложение закрывается;
- **portable-сборка** обновляет себя сама: ждёт выхода процесса, копирует новый `.exe` поверх старого и запускает его;
- **zip** открывается в Проводнике для ручной распаковки.

Скачанный файл должен находиться в отдельном временном каталоге, созданном приложением; запуск произвольного `.exe` или `.zip` из другого места заблокирован.

Для публикации обновления создайте GitHub Release с тегом версии (например, `v0.2.0`) и приложите новый `YMRPC-Next.exe` или установщик. GitHub автоматически добавляет digest к загруженным ассетам; без него автообновление этот файл не примет.

## Данные и приватность

Всё хранится локально в `%LOCALAPPDATA%\YMRPC-Next`:

| Путь | Содержимое |
|---|---|
| `config.json` | настройки |
| `token.bin` | OAuth-токен, зашифрованный DPAPI |
| `stats.db` | история прослушиваний (SQLite WAL) |
| `cache\art\` | кэш обложек |
| `logs\` | логи приложения |

- Оверлей и API доступны только с `127.0.0.1`. Сервер проверяет заголовок `Host`, отдаёт CORS только loopback-origin, добавляет CSP/`nosniff` и не раскрывает пути к файлам.
- Токен шифруется Windows DPAPI. Если DPAPI недоступен или сохранение не удалось, приложение не пишет токен в открытом виде и откатывает вход.
- Обложки скачиваются только по HTTPS с публичных адресов; локальные, приватные и link-local адреса блокируются, редиректы проверяются, MIME и магические байты изображений валидируются.
- Discord получает только публичные HTTPS-ссылки; `yandexmusic://` преобразуется в HTTPS. Внешние ссылки интерфейса открываются после проверки allowlist.
- Экспорт CSV экранирует формулы (`=`, `+`, `-`, `@`, tab, CR), чтобы Excel не выполнял содержимое ячеек.
- Обновления принимаются только с GitHub, требуют SHA-256 digest и проверяются перед запуском.
- Телеметрии и отправки данных на сторонние серверы нет.
- Наружу уходят только запросы, необходимые для работы: Discord IPC (локально), Яндекс API, LRCLIB, iTunes/Deezer для поиска обложек и GitHub для обновлений.
- Автозапуск прописывается в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` и удаляется при отключении.

Сбросить всё можно, удалив папку `%LOCALAPPDATA%\YMRPC-Next` при закрытом приложении.

## Известные ограничения

- Приложение только для Windows: SMTC, DPAPI, `RegisterHotKey` и автозапуск используют Win32 API.
- Управление воспроизведением работает для треков Windows SMTC; Ynison — только чтение.
- Оверлей не является частью видеопотока — его добавляют в OBS как Browser Source.
- Portable-обновление копирует `.exe` поверх текущего; если папка защищена от записи, обновление не установится.
- Сборка не подписана, поэтому SmartScreen может показывать предупреждение.
